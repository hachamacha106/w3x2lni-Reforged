# W3x2lni Reforged 1.2.0

Released 2026-10-11.

This release adds optional inherited-field references to LNI exports and improves
progress and reporting for large JASS checks. LNI, OBJ and SLK conversion defaults
remain unchanged.

## Download

Download `w3x2lni-reforged-1.2.0-windows-x86.zip` from this release's assets.
Extract the entire ZIP into a new folder and launch `w3x2lni.exe`. Use `w2l.exe`
for command-line conversion. The included `warcraft-current` dataset is selected.
Use the portable ZIP to run the application; GitHub's source-code archives are
for development.

## Inherited fields as comments

Select **To LNI → Advanced → Show inherited fields as comments** to include
readable reference values in exported object `.ini` files. The option is off by
default. Existing overrides remain active, and untouched stock objects are not
added. Leaving the new comments unchanged preserves inheritance from the parent
object and selected Warcraft dataset.

For example:

```ini
-- Area of Effect
-- Area = 900.0
-- Animation Names
-- Animnames = "" -- (no default)
```

References reflect the effective values available during export, including map
object overrides. When an effective value is unavailable, the field retains its
readable label and receives a commented edit template marked `(no default)`:
integer `0`, real `0.0`, or string `""`. Warcraft boolean object fields use numeric
`0`/`1`, so their template is `0`. A template is not a known inherited default and
has no effect while commented.

To make an explicit override, remove `--` from the value line and edit the value.
For multiline values, uncomment the entire assignment. For a partially overridden
array, edit the existing active array; the full effective array shown in comments
is for reference and should not become a second definition. Re-export after
changing the selected dataset to refresh reference values.

Field metadata without a valid editable-field definition is excluded safely.
Existing unknown object records, skin sidecars, native profiles and zero/empty
value overrides retain their preservation behavior. The new setting changes
comment output, not the meaning of active LNI assignments.

## Clearer script checks and large reports

Conversion now shows when pjass is checking the input or output script. Large
checker reports are grouped to reduce repeated interface updates while preserving
full raw output, line numbers and visible failure results. Target-dataset and
map-declaration checks retain their separate labels.

pjass remains report-only: a failed check does not block conversion or change its
exit status. These changes do not repair scripts automatically or suppress errors.
Lua maps continue to skip pjass explicitly.

## Verification and compatibility

Regression coverage checks that commented references do not become active
assignments, active zero/empty values remain intact, and uncommenting a reference
creates only the intended override. Tests cover missing-value templates,
multiline/sparse arrays, malformed metadata, map overlays, dataset changes,
native profiles and large checker reports using current and legacy Warcraft data.
Native Windows conversion round trips compare rebuilt object data with references
off and on.

The maintainer reported successful use of the inherited-field preview. That report
does not establish separate World Editor or gameplay acceptance for every map.
A pjass pass checks syntax and declarations, not gameplay. Test converted maps in
your intended Warcraft III version, and keep OBJ or LNI as the editable source.
SLK settings can remove editor-only information.

## Native runtime and credits

StormLib 9.40, static zlib 1.3.2 and the checksum-pinned pjass helper keep the same
dependency pins as 1.1.5. Release checks build and probe StormLib from those pins;
the other 21 native files retain byte verification against upstream 2.7.3. This
release does not update CascLib or the remaining native runtime.
